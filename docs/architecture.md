# 아키텍처

## 개요

```
           ┌──────────── DOM (React) ─────────────┐
 사용자 ─▶ │ SetupScreen → RideScreen → CompleteScreen │
           │   객실 실내(CSS)·HUD·패널               │
           └───────┬───────────────┬──────────────┘
                   │ rAF loop      │ 4Hz HUD setState
     epochNow() ─▶ elapsedSec ─▶ sampleJourney(journey, t) ─▶ SimSample
                                         │
                   ┌─────────────────────┼─────────────────────┐
                   ▼                     ▼                     ▼
          Renderer (Canvas 2D)     AudioEngine (WebAudio)   이벤트(차임·문)
          scene.ts 레이어 합성       속도/가속도/구간 기반      journey.events
```

- **Next.js 16 (App Router) + React 19 + TypeScript**. 페이지 하나(`/`)가 정적으로 빌드되고 모든 동작은 클라이언트에서 한다. 백엔드 없음.
- **DOM** 은 객실 실내와 UI, **Canvas 2D** 는 창밖 풍경만 그린다 (기획 §11). PixiJS/Three.js 는 도입하지 않았다 — 현재 렌더 비용이 프레임당 약 1ms 라 필요 없다.
- **Zustand** 는 세션·기록·설정만 다룬다. 프레임 단위 값은 스토어에 넣지 않는다.

## 시뮬레이션 엔진 (`src/sim`)

### 여정 생성 `buildJourney({ stationIds, totalSec })`

1. 역 목록 → 인접 구간(`line2.ts`의 `LineSegment`)
2. 고정 시간 = 출발 정차(10s) + 중간역 정차(20s × n−1) + 종착 정차(≥6s)
3. 남는 주행 시간을 구간별 추정 운행시간 비율로 분배
4. 각 구간: 목표 순항속도(21m/s ≈ 76km/h)로 시간 T 를 채우는 거리 D 계산
   `T = K·v + D/v`, `K = (1−σa)/a_acc + (1−σd)/a_dec` (σ = 램프 거리계수)
   - D 가 최소 연출 길이보다 짧으면 D 를 고정하고 v 를 2차식으로 풀어 맞춘다
   - D 가 길면 남는 거리를 연출 구간의 `stretch` 가중치로 분배 (한강·승강장·갱문은 고정, 터널·시가지가 늘어남)
5. 결과: `sections`(트랙 좌표상 연출 구간), `phases`(시간순 상태), `events`(차임·문·도착)

총 시간은 항상 목표 집중시간과 같다 (`scripts/check-sim.ts` 가 검증).

### 가감속 `profile.ts`

가속도 모양 함수 g(x)를 수치 적분한 룩업 테이블. 가속은 저속에서 일정 견인력 → 고속에서 감소, 감속은 일정 제동 → 정차 직전 완화. 가속도가 0에서 시작·종료하므로 출발/정차 순간 저크가 없다. 최대 |a| ≈ 1.1m/s².

### 상태

`IDLE · BOARDING · DEPARTING(가속) · MOVING(순항) · APPROACHING(감속) · ARRIVED · PAUSED · COMPLETED`
`sampleJourney(j, t)` 가 이진 탐색으로 phase 를 찾고 위치·속도·가속도·문 열림·진행률을 계산한다. PAUSED 는 세션 타이밍(일시정지 시각)으로 표현되어 sim 시간이 멈춘다.

### 시계·복구 정책 (`clock.ts`, `useAppStore.ts`)

- 세션 = `{ startedAt, pausedAccumMs, pausedAt }` (epoch ms). 경과 = now − startedAt − 일시정지 누적.
- `epochNow()` 는 performance.now() 로 부드럽게 보간하되 Date.now() 와 40ms 이상 어긋나면 재동기화 (절전 복귀 대응).
- **탭 비활성화**: rAF 가 멈추면 렌더링은 중단, 500ms 인터벌로 이벤트·오디오·완료 판정만 유지.
- **새로고침**: 세션이 localStorage 에 있으므로 벽시계 기준으로 그대로 이어진다(새로고침 동안에도 시간은 흐름). 일시정지 중이었다면 일시정지 상태로 복구. 그 사이 종료 시각이 지났으면 즉시 완료. 오디오는 사용자가 "소리 켜기"를 다시 눌러야 한다(자동재생 정책). 새로고침 직후 지난 이벤트(차임 등)는 재생하지 않는다.
- **중복 기록 방지**: `completeSession` 은 세션 id 가 이미 기록돼 있으면 추가하지 않는다.

## 렌더러 (`src/render`)

### 좌표

창 중앙 = 열차 위치 `cam`(시뮬레이션 m). 레이어마다 시차 계수 s(u/m, u = 창 높이 1%).
`screenX = W/2 + (m − cam)·s·u`. 창은 서쪽을 향하고 열차는 북쪽(오른쪽)으로 달리므로 풍경은 오른쪽→왼쪽으로 흐른다.

### 레이어 (먼 곳 → 가까운 곳)

| 레이어 | s | 내용 |
|---|---|---|
| 하늘 | – | 그라디언트, 해/달·별, 구름(바람 drift) |
| 산 2겹 | 0.014 / 0.028 | fbm 능선, 연무 |
| 원경 시가지 | 0.075 | 강 건너 아파트·빌딩 실루엣, 야간 창불 |
| 수면 | 행별 0.08~3.5 | 깊이별 시차 물결, 원경 반사, 햇빛 반짝임/노을 반사 기둥 |
| 선유도·유람선 | 0.24 / 0.3 | 섬 숲·옛 정수장·선유교, 하류로 가는 유람선 |
| 양화대교 | 0.42 | 아치·교각·수면 반사·양방향 차량·가로등 |
| 중경 | 0.62 | 아파트 단지(동 번호), 오피스, 둔치·강변도로 |
| 근경 | 1.55 | 상가(간판)·빌라·옥상 물탱크·가로수(가을 은행)·전신주와 전선·한강공원 |
| 승강장 벽 | 2.3 | 지하: 타일 벽·역명판·광고 / 고가: 지붕·유리 난간 |
| 승강장 | 3.0 | 기둥, 기다리는 승객 |
| 선로 구조물 | 4.2 | 방음벽 / 당산철교 트러스 / 스크린도어(개폐) / 갱문 옹벽 / 터널 벽(조명·케이블·유도등·신호기) |
| 최근경 | 7.2 | 전차선 지지대 (속도 비례 모션 블러) |
| 유리 | – | 시간대 틴트, 실내 반사(터널에서 강해짐), 광택, 비네팅 |

- 오브젝트 종류는 앵커 위치가 속한 연출 구간이 결정 → 느린 레이어일수록 넓은 범위를 비춰 구간 전환이 자연스럽게 엇갈린다.
- 실외가 완전히 가려지면(터널·지하 승강장) 원경~근경 레이어를 건너뛴다.
- 주행 진동(속도 비례 상하), 가감속 관성 기울기, 손잡이 감쇠 진자 — 모션 감소 시 끔.

### 성능

- 건물·나무·사람·구름·역명판은 `SpriteCache`(오프스크린 캔버스, DPR 반영)로 1회 드로잉.
- `alpha:false` 컨텍스트, DPR 최대 2. 렌더 시간 이동평균 24ms 초과 시 DPR 1·품질 0.6 으로 자동 하향.
- 측정: 1440×900 headless Chrome 에서 60fps, 렌더 0.5~1.5ms/frame.

## 오디오 (`src/audio`)

WebAudio 실시간 합성. 채널별 GainNode → 마스터 → 컴프레서.
- 주행음: 브라운 노이즈 로우패스(속도↑ → 음량·밝기↑) + 고속 바람 노이즈 + 가감속 시 인버터음(주파수 ∝ 속도)
- 레일: 트랙 위치가 이음매(지상 25m, 철교 12m)를 지날 때 대차 축 간격(2.1m, 12m)/속도 로 "덜컹-덜컹" 예약 재생, 철교에서는 낮고 길게
- 터널: 컨볼버 리버브 send 증가
- 차임(자체 작곡), 문 경고음·공압·닫힘음, 객실 공조 + 패드
- 사용자 클릭 이후에만 AudioContext 생성. 채널별 볼륨·전체 음소거 저장.

### 조사했지만 쓰지 않은 것

- 공공데이터포털 「서울교통공사_역간거리 및 소요시간」 오픈API: 같은 데이터, 활용신청·인증키 필요 → 정적 CSV 로 충분
- 실시간 도착/시간표 API: 집중 세션은 실제 열차와 동기화하지 않으므로 불필요
- 서울교통공사 "최단경로" API: 공개 API 로 확인되지 않음. 환승이 필요해지면 역간 소요시간 + 환승 소요시간(공공데이터) 으로 자체 계산 가능

### 창 방향 규칙

승객은 여정 내내 **진행 방향 왼쪽 창**을 본다 (`windowFacing`). 북쪽 진행(당산→합정) = 서쪽 창 → 양화대교·선유도·하류 노을, 남쪽 진행(강변→잠실나루) = 동쪽 창 → 올림픽대교·롯데월드타워. 노을 해는 서향 창에서만 보이며 창 방향이 바뀌면 서서히 사라진다.

### 연출 데이터 `scenery.ts`
구간별 풍경 순서와 최소 길이(시뮬레이션 m)·stretch 가중치. 물 구간은 `variant`(hangang-yanghwa / hangang-jamsil / stream)로 랜드마크가 결정된다.
전용 레이아웃: 당산→합정(한강 600m → 갱문 → 터널), 강변→잠실나루(한강 760m), 한양대→뚝섬(중랑천 130m). 그 외는 지상/지하 조합에 따른 기본 템플릿(지하→고가는 portal-out).
